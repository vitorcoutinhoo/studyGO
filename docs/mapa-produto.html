Tudo que existe hoje no Plantão

Mapa completo de rotas, telas, fluxos de navegação e padrões de visualização do sistema — como está implementado agora, direto do código.

18 rotas ~24 telas 6 serviços de domínio 2 perfis de acesso React · TypeScript · Vite

Stack & guarda de rotas

React + TypeScript sobre Vite, roteamento com react-router-dom, transições animadas com framer-motion, Tailwind para estilo e lucide-react para ícones. Geração de PDF via @react-pdf/renderer. Cliente HTTP em axios centralizado em services/api.ts.

▲ Guarda de rota é só de interface. AdminRoute lê o papel do usuário direto do localStorage e redireciona quem não é admin/gerente — não valida token nem sessão. Funciona como atalho de UX; a autorização real precisa estar garantida no backend.

Fluxos de navegação

Sessão típica — admin ou gerente

Login → /home, com os 4 blocos de atalho. Normalmente começa pela Escala (/scale/month) revisando o calendário do mês; usa Sugestão para gerar o próximo rodízio e confirma os blocos. Do mês, salta direto para Relatório já filtrado naquele período e imprime o PDF. Em paralelo, cuida de Colaboradores (/users): cadastra novos, entra em detalhes → histórico de plantões (PDF individual) ou edição. Da lista, envia convites de acesso e ajusta permissões. A seção "Administração" fecha o ciclo: Financeiro (valores e feriados), Cargos/Setores (taxonomia usada nos formulários de colaborador) e Modelos de e-mail. O dia a dia do plantão em si acontece em /duty: criar, finalizar, pagar ou excluir.

Sessão típica — colaborador

Login → /home mostra só os próprios plantões ativos, em cards. Tocar um card abre um modal para registrar observação e avançar o status (Iniciar → Concluir). Se tentar acessar uma rota administrativa direto pela URL, AdminRoute devolve para /home. Na prática, as únicas telas alcançáveis são /home e /perfil.

▲ Pequena inconsistência de papel. A barra lateral marca as seções Colaboradores/Plantões/Escala/Relatórios como visíveis para todos (adminOnly: false no nível da seção), mas cada página individual é protegida por AdminRoute — um colaborador comum vê o link e é redirecionado só ao clicar. Home.tsx também trata só role === 'admin' como visão administrativa, enquanto o restante do app trata admin e gerente como equivalentes.

Convenção responsiva dominante

Praticamente toda tela segue o mesmo split: hidden md:block para a versão desktop (tabela/grade) e md:hidden para pilha de cards no mobile com barra de ação fixa embaixo — não é exclusividade do DataTable, é o padrão de layout do projeto inteiro.
